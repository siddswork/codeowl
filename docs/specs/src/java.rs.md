# src/java.rs
## Summary
The Java language pack's reading layer: the Java counterpart of the TypeScript and Rust extractors, plus the Java parts of import reading and resolution. It does two jobs. First, `extract_file` walks one `.java` file with tree-sitter (a library that turns source text into a syntax tree) and records its declarations. Every class, interface, enum, `@interface` and record becomes a container, since a record is just a restricted final class. Methods, constructors and annotation elements become callables, and fields and interface constants become values. Nested types are walked fully, while method bodies, statements, lambdas and anonymous classes are skipped, because CodeOwl does not write specs for those. Each container carries two fingerprints: one over everything in it, and one over only its public surface, so edits to a body do not mark dependents stale but a change to a public signature does. Second, the import half: `extract_imports` reads `import` lines (and classes named by their full path with no import) into package and name pairs, and `resolve_imports` turns them into links in three ways. Explicit imports are matched to the `.java` file whose path ends with the matching package folders, so any project layout works with no configuration. Same-package classes, which Java lets you use with no import, are found by scanning each file's text for its neighbours' names. Fully-written class names are linked too. Annotation names are reduced to their plain form so a generated interface that writes them fully qualified still matches. Everything here is Java-specific; Rust and TypeScript keep their equivalents in their own files.

## `extract_file`
`pub fn extract_file(source: &str, rel_path: &str) -> Vec<ExtractedSymbol>`
### Summary
Reads one Java file and returns the declarations in it: every top-level class, interface, enum, annotation type or record, together with their members.
### Behavior
Creates a tree-sitter parser (a library that turns source text into a syntax tree) with the bundled Java grammar; loading the grammar is assumed always to work. If the text cannot be parsed at all it returns an empty list. Otherwise it goes through the top-level items of the file in order and hands each to `visit_item`, which adds symbols to the output, so declarations come out in source order. Nothing from the syntax tree escapes the function, since the tree is dropped when it returns and only plain owned symbols are returned. Package and import lines at the top are not turned into symbols here; `extract_imports` reads those separately.

- externals: tree_sitter

## `visit_item`
`fn visit_item(
    node: Node,
    parent_id: Option<&str>,
    source: &str,
    file: &str,
    out: &mut Vec<ExtractedSymbol>,
)`
### Summary
Looks at one Java declaration and records the right kind of symbol for it: a type becomes a container, a method or constructor becomes a callable, and a field or constant becomes a value. Anything else is ignored.
### Behavior
`parent_id` is the enclosing type, or `None` at the top of the file. It dispatches on the syntax node's kind:
- class, interface, enum, annotation type (`@interface`) and record declarations go to `visit_container`, with the language's own word recorded as the raw kind (`class`, `interface`, `enum`, `@interface`, `record`).
- A method becomes a callable named after the method. A constructor and a compact constructor (a record's shorthand) become a callable with the name `<init>` and raw kind `constructor`. An annotation element declaration becomes a callable with raw kind `element`.
- A field or interface constant becomes one value symbol per declared name, because `int a, b;` is one declaration binding several names. The raw kind is `field`, or `constant` for an interface constant. A declarator whose name cannot be read is skipped.
- The tail of an enum body (the members after the `;` that follows the constants) is walked child by child, re-entering this function with the same parent so those members attach to the enum.

Statements, method bodies and lambdas are never entered. Unrecognised node kinds, such as imports or comments, are silently skipped. It appends to `out` and returns nothing.

## `visit_container`
`fn visit_container(
    node: Node,
    raw: &str,
    parent_id: Option<&str>,
    source: &str,
    file: &str,
    out: &mut Vec<ExtractedSymbol>,
)`
### Summary
Records one Java type (a class, interface, enum, annotation type or record) as a container, walks its members, and computes the two fingerprints that decide when its specs and dependents go stale: one over everything in it, and one over only its public surface.
### Behavior
The id is `<file>::<Name>` at the top of a file, or `<parent id>::<Name>` for a nested type. It walks the type's body, calling `visit_item` for each member with this type as parent, so members and nested types are appended to the output first. Nested types recurse fully.

Whole-type fingerprint (`source_hash`): the signature (the declaration text before the body) plus each direct member's `source_hash`, one per line, hashed. A nested type's own hash already covers its members, so folding it in covers them transitively.

Public-surface fingerprint (`interface_hash`, only for exported types, otherwise `None`): a top-level type is always exported, and a nested type is exported only if it is `public` or `protected`. For an exported type, it starts from the signature and adds each public member's own signature:
- A field is included if it is a constant (an interface member, which is implicitly public, so the keyword is not required), or its signature says `public` or `protected`. The assigned value is stripped before the visibility test and before hashing, so editing a value does not change the shape, and a private field whose string value happens to contain the word "public" is not mistaken for public. The stored signature itself keeps the value, because the Quarkus code reads a Kafka channel name out of it.
- A method is included in an interface or annotation type unless it is marked `private`, because interface methods and annotation elements are implicitly public; otherwise it needs `public` or `protected` in its signature. Methods are hashed exactly as written, with no value stripping since Java methods have no default parameter values. A known imprecision is that a string in an annotation argument containing the standalone word "public" could count a method as public.

Finally the container is inserted into the output before its members, so order stays parent then children. It carries the line range, the preceding doc comment, the annotations as markers, the parent id, and the member ids. Nothing is returned.

## `push_leaf`
`fn push_leaf(

### Summary
Records a simple Java declaration, such as a method, whose name is written in the declaration itself. It is the shortcut for the common case before the more general helper.
### Behavior
Reads the node's `name` field as text. If the node has no readable name it returns without adding anything. Otherwise it passes that name along with the kind, raw kind, parent id, source and file to `push_named_leaf`, which builds and appends the symbol. It exists so callers do not repeat the name lookup, while declarations whose name is not in a `name` field, such as a constructor (named `<init>`) or a field with several declarators, use `push_named_leaf` directly with a name they supply. It appends to `out` and returns nothing.

## `push_named_leaf`
`fn push_named_leaf(
    node: Node,
    name: &str,
    kind: SymbolKind,
    raw: &str,
    parent_id: Option<&str>,
    source: &str,
    file: &str,
    out: &mut Vec<ExtractedSymbol>,
)`
### Summary
Builds and records the symbol for a Java method, constructor, field or constant, using a name supplied by the caller. This is where the leaf declarations' ids and fingerprints are decided.
### Behavior
The id is `<parent id>::<name>`, or `<file>::<name>` when there is no parent. The signature is the declaration text before its body (`signature_before_body`). The symbol is exported only when it has no parent and has a `public` or `protected` modifier; a member is never counted as exported on its own, because it is reached through its type and not imported separately. `source_hash` is a hash of the whole declaration text, body included. `interface_hash` is a hash of the signature alone, and exists only when the symbol is exported, so body edits leave it unchanged. The symbol also records its line range, the preceding doc comment, its annotations as markers, the parent id, and no children. It appends to `out` and returns nothing. In practice leaves almost always have a parent, so they rarely have an interface hash; the container's own public-surface hash covers their signatures.

## `signature_before_body`
`fn signature_before_body(node: Node, source: &str) -> String`
### Summary
Pulls out a declaration's signature — everything before its `{` body: modifiers, keyword, name, type parameters, `extends`/`implements`, parameter list, return type. Used for both types and members, since Java writes all of that the same way up to the brace.
### Behavior
Takes the source text from the declaration's start byte to wherever its `body` node begins. If there is no body — an abstract or interface method, a bodyless `record Foo(int a);` — it goes to the end of the declaration instead. Then it trims trailing whitespace, a trailing `;`, and any whitespace before that. The result is the header exactly as written in the source, possibly spanning several lines.
### Depends on
- externals: tree_sitter

## `has_public_or_protected`
`fn has_public_or_protected(node: Node) -> bool`
### Summary
Reports whether a declaration is marked `public` or `protected`. Used to decide whether a *nested* type or a member is visible outside its class, and so whether it's a valid target for a reference edge.
### Behavior
Finds the declaration's `modifiers` node (via `modifiers_of`); if there isn't one — the declaration is package-private or `private` — returns `false`. Otherwise returns `true` if any modifier is the keyword `public` or `protected`. Doesn't look at `private` explicitly: anything that isn't `public`/`protected` is treated as not exported.
### Depends on
- externals: tree_sitter

## `is_pub_or_protected_field_signature`
`fn is_pub_or_protected_field_signature(signature: &str) -> bool`
### Summary
Checks, from a member's already-stored signature text, whether it is declared `public` or `protected`. It is used when computing a type's public-surface fingerprint, where only the stored text is left and no syntax node can be re-examined.
### Behavior
Splits the signature on whitespace and returns true if any whole token equals `public` or `protected`. It is an exact token match, not a substring search, so a field named `publicApiUrl` is not mistaken for a modifier. Because the whole signature is scanned, a stray `public` token anywhere in it would count, which is why callers strip a field's assigned value first so a string such as `"public only to admins"` cannot supply one. Package-private (no modifier) and `private` give false. Pure function with no failure mode.
### Depends on
- (none)

## `modifiers_of`
`fn modifiers_of(node: Node<'_>) -> Option<Node<'_>>`
### Summary
Finds a declaration's `modifiers` node — the group holding `public`, `static`, `final`, and any annotations — smoothing over a grammar inconsistency in how different declaration kinds expose it.
### Behavior
Tries `child_by_field_name("modifiers")` first, which works for most declaration kinds. If that returns nothing, falls back to scanning the direct children for a node of kind `"modifiers"` — a few node types only attach it as a plain child, not a named field. Returns `None` when there are no modifiers at all (a package-private class with no annotations).

## `leading_doc`
`fn leading_doc(node: Node, source: &str) -> Option<String>`
### Summary
Pulls the Javadoc comment directly above a declaration and returns its text with the `/**`, `*/`, and per-line leading `*` markers stripped. `None` when there's no doc comment.
### Behavior
Walks backwards from the declaration through its preceding siblings in the parse tree, accepting only comments that are *directly adjacent* — each has to end on the line the next thing begins, with no blank line between. A blank line, or any non-comment node, ends the walk, so a stray comment two declarations up isn't misattributed.

For each adjacent comment: a Javadoc `/** … */` block contributes its cleaned-up lines (via `doc_comment_body`); a plain `//` or `/* */` comment is stepped over without adding text. Because the walk runs backwards, lines are collected in reverse and flipped at the end; an empty result becomes `None`.

Java annotations don't get in the way here — they sit inside the declaration's `modifiers` node, not as preceding siblings.
### Depends on
- externals: tree_sitter

## `doc_comment_body`
`fn doc_comment_body(raw: &str) -> Option<Vec<String>>`
### Summary
Turns a raw Javadoc comment string into its content lines, stripped of the comment markers. Returns `None` for anything that isn't a `/** … */` block, which is how `leading_doc` tells a real doc comment apart from an ordinary comment to step over.
### Behavior
Only proceeds if the string both starts with `/**` and ends with `*/` — otherwise `None`. For the text between, it splits into lines and for each one: trims whitespace, drops a leading `*`, trims again, and keeps it only if non-empty. So `* @param x the value` becomes `@param x the value` and blank `*`-only lines are dropped.

- (none)

## `bare_annotation_name`
`pub(crate) fn bare_annotation_name(marker: &str) -> &str`
### Summary
Reduces a Java annotation as written, such as `@Path("x")` or `@jakarta.ws.rs.Path(...)`, to just its plain name, `Path`. Code that checks annotations compares against that plain name, so it keeps working whichever way the annotation was spelled.
### Behavior
Removes leading whitespace and any leading `@`, cuts the text at the first `(` or space, and then keeps only what follows the last `.`, which drops a package qualifier. The package-stripping step matters for build-generated interfaces, which have no reason to import names and so write every annotation fully qualified; without it, every bare-name comparison would silently fail to match them. The three callers that once each had their own copy (the entity check and two in the Quarkus code) share this one, which is fine because the markers only ever come from this same language pack. It returns a slice of the input and cannot fail; an empty or odd input gives an empty or unchanged name.

## `extract_imports`
`pub fn extract_imports(source: &str, _rel_path: &str) -> FileImports`
### Summary
Reads a Java file's `import` lines and returns them as pairs of package and name, plus any fully-written references to other classes that appear in the code without an import. This is the raw material for linking Java files to one another.
### Behavior
Parses the file with the Java grammar and, if parsing fails, returns an empty result. For each top-level `import` declaration it reads the dotted path and splits it at the last dot:
- `import a.b.C;` becomes specifier `a.b` and name `C`.
- `import static a.b.C.m;` becomes specifier `a.b.C` and name `m`, so the class stays in the specifier. Being `static` does not change extraction, only how it is resolved later.
- `import a.b.*;` becomes the whole path as specifier and `*` as the name. A star import names no single declaration, so it resolves to nothing; most Java projects forbid them anyway.
- A single-segment import from the default package (`import C;`) has nothing to key on and is skipped.

A declaration with no readable path is skipped. After the imports, `extract_qualified_refs` fills the separate qualified-references list from the rest of the file, for classes reached by their full name with no import statement. The file's own path is not used. Cannot fail.
### Depends on
- `src/imports.rs::FileImports` — crate::imports
- `src/imports.rs::ImportRef` — crate::imports
- externals: tree_sitter

## `extract_qualified_refs`
`fn extract_qualified_refs(node: Node, source: &str, out: &mut Vec<ImportRef>)`
### Summary
Finds places where Java code names another class by its full path (`a.b.C`) instead of importing it. Java allows this, and it can coexist with an import of a different class with the same short name, so these references need their own scan to be linked.
### Behavior
Walks the whole syntax tree recursively, skipping `package` and `import` declarations entirely, since the import loop already handles those. When it reaches a dotted node, namely a scoped type name (as in a parameter type), a scoped identifier (as in an annotation name), or a field access (how the parser reads `a.b.C.method(...)`, as a method call whose object is the dotted access), it takes the node's text, splits at the last dot into a specifier and a name, and pushes an `ImportRef`. It does not recurse into that node, since its dotted text is already consumed. Text without a dot is ignored.

It records every dotted name without checking whether it is a package: a field access on a local variable such as `t.value` is recorded too, and simply fails to match any file later, so resolution is the filter and none is applied here. Comments are separate tokens in the tree, so a class name in a Javadoc `{@code a.b.C}` is not picked up, which avoids a false positive that an earlier plain-text scan had. It appends to `out` and returns nothing.
### Depends on
- `src/imports.rs::ImportRef` — crate::imports
- externals: tree_sitter

## `resolve_imports`
`pub fn resolve_imports(
    root: &Path,
    file_imports: &HashMap<String, FileImports>,
    graph: &Graph,
) -> Vec<ResolvedImport>`
### Summary
Turns the Java imports found across the repo into links to the declarations they name, and adds the links Java allows without any import line: classes used from the same package, and classes named by their full path.
### Behavior
Visits files in sorted path order so the saved edge list is stable between runs. In three stages it builds one list of `ResolvedImport`:
1. Explicit imports. Each import statement of each file becomes one edge, with its target worked out by `resolve_explicit`, which matches the fully-qualified name to a `.java` file whose path ends with the matching package directories, so any project layout works with no configuration. Unresolved ones are kept with no target.
2. Same-package edges from `same_package_edges`. Java lets one class use another in the same package with no import, so this scans each file's source text for such names. That is why the repo root is read here: the graph does not keep method bodies, so the text has to be read from disk.
3. Cross-package qualified edges from `cross_package_qualified_edges`, for classes reached by their fully-qualified name with no import. It is given the edges found so far so it can avoid duplicating or contradicting them.

Returns the combined list. It cannot fail itself; problems appear as edges with no target.
### Depends on
- `src/graph.rs::Graph` — crate::graph
- `src/imports.rs::FileImports` — crate::imports
- `src/resolve.rs::ResolvedImport` — crate::resolve
- externals: std

## `cross_package_qualified_edges`
`fn cross_package_qualified_edges(
    sorted_files: &[(&String, &FileImports)],
    file_imports: &HashMap<String, FileImports>,
    existing: &[ResolvedImport],
    graph: &Graph,
) -> Vec<ResolvedImport>`
### Summary
Adds links for Java classes a file uses by writing out their full path (such as `com.acme.fight.Fight`) with no import line. Without it, a file whose only link to another class is a fully-written name would look unconnected, and a change to that class could not mark the file stale.
### Behavior
First it builds, once, a map from each file to the set of targets it already reaches through earlier edges, so it does not rescan all edges for every file. Then for each file, in sorted order, and each of its qualified references, it resolves the name the same way an explicit import is resolved (`resolve_explicit`, which does not care how the name was written), so no new resolution rules are introduced. It skips a reference that does not resolve, one whose target is in the same file as the reference, and one whose target the file already reaches. That last check compares the target's id, not its simple name, so two different classes both called `Fight`, as in one mapper that deals with two of them, each still get an edge, because Java's same-package shadowing rule does not apply to either. Each surviving reference becomes a `ResolvedImport` with the target set. Returns only the new edges, in file order.
### Depends on
- `src/graph.rs::Graph` — crate::graph
- `src/symbol.rs::SymbolId` — crate::graph
- `src/imports.rs::FileImports` — crate::imports
- `src/resolve.rs::ResolvedImport` — crate::resolve
- externals: std

## `fqn_to_file`
`fn fqn_to_file<'a>(fqn: &str, file_imports: &'a HashMap<String, FileImports>) -> Option<&'a str>`
### Summary
Finds the Java file that a fully-qualified class name points to, such as `com.acme.Fight`, by matching it against the ends of the repo's file paths. It works for any project layout with no configuration.
### Behavior
Turns the name into a path by replacing dots with slashes and adding `.java`, so `a.b.C` becomes `a/b/C.java`. It then keeps every indexed file whose path equals that or ends with `/a/b/C.java`, which makes it independent of where the source folder is (`src/main/java`, a module folder, or anything else). The matches are sorted and the first is returned, so when the same name exists under two source roots, such as main and test, the alphabetically first path wins and the result is deterministic. A longer name such as `a.b.C.member` (a static import) maps to `a/b/C/member.java`, so callers pass only the class part. It returns `None` when nothing matches. Note the pick among several matches is by path order and is not checked for correctness. Pure lookup, no failure mode.
### Depends on
- `src/imports.rs::FileImports` — crate::imports
- externals: std

## `resolve_explicit`
`fn resolve_explicit(
    specifier: &str,
    name: &str,
    file_imports: &HashMap<String, FileImports>,
    graph: &Graph,
) -> Option<SymbolId>`
### Summary
Resolves a single Java import, a package and a name, to the declaration it points at, or to nothing when it points outside the repo or at something CodeOwl does not track.
### Behavior
A star import (`*`) returns `None`, because it names no single declaration. Otherwise it tries two readings in order:
1. The usual case, `import a.b.C;`: the package plus name together form the class's full name. It looks up the file for `a.b.C` with `fqn_to_file` and then the symbol `<file>::C` in the graph, and returns it if found.
2. If that fails, the specifier itself may be a class, as in `import static a.b.C.m;` or `import a.b.Outer.Inner;`. It finds the file for the specifier, takes the class name as its last segment, and tries three symbol ids in this order: a nested member or static method (`<file>::Class::name`), a top-level symbol with that name (`<file>::name`), and finally the enclosing class itself (`<file>::Class`). The last fallback is deliberate: pointing at a method would be call-level precision, which is deferred, so a static import of a method links to its class.

The first id the graph knows is returned. An external package, a missing file, or a file with no matching declaration gives `None`. The match among several candidate files is only by path suffix, so a duplicated name under two source roots resolves to the first by path order. It works the same whether the name came from an import, a same-package guess, or a fully-qualified reference, because it does not care how the name was written.
### Depends on
- `src/graph.rs::Graph` — crate::graph
- `src/symbol.rs::SymbolId` — crate::graph
- `src/imports.rs::FileImports` — crate::imports
- externals: std

## `same_package_edges`
`fn same_package_edges(
    root: &Path,
    sorted_files: &[(&String, &FileImports)],
    graph: &Graph,
) -> Vec<ResolvedImport>`
### Summary
Finds the links between Java classes in the same package, which need no import line, by looking for each neighbour class's name in a file's text. Without this, a file that only uses a class from its own folder would look unconnected to it.
### Behavior
First it gathers every top-level container in the graph, meaning classes and interfaces whose id has no nested `::` after the file, and including table classes (entities) that the generic pipeline has already retagged as schema symbols, since an entity used from the same package must resolve just like an explicitly imported one.

Then for each file, in sorted order, it finds the sibling containers: those declared in a different file in the same directory (the directory stands in for the package). If there are none it moves on. It reads the file's source from disk, skipping the file if it cannot be read, such as a file deleted mid-watch. For each sibling name it applies two rules. An explicit import of that exact simple name hides the guess and skips it, matching Java's own rule that an explicit import wins over a same-package class; this matters when two different classes share a simple name, as `lang3.Streams` and `lang3.stream.Streams` do. Otherwise, if the name appears in the text as a whole word (`mentions_identifier`), it adds an edge to that sibling, with the package name as the specifier so it is visibly not a written import.

Returns the new edges. It is a text match, so a name that appears only in a comment or string also creates an edge, an accepted over-approximation. The source is read once per file that has siblings, which is why this stage needs the repo root.
### Depends on
- `src/graph.rs::Graph` — crate::graph
- `src/symbol.rs::SymbolId` — crate::graph
- `src/imports.rs::FileImports` — crate::imports
- `src/resolve.rs::ResolvedImport` — crate::resolve
- `src/symbol.rs::SymbolKind` — crate::symbol
- externals: std

## `mentions_identifier`
`fn mentions_identifier(text: &str, name: &str) -> bool`
### Summary
Whole-word search: reports whether `name` appears in `text` as a standalone identifier, not as a fragment of a longer name. This is what `same_package_edges` uses to decide a file actually references a sibling class.
### Behavior
Scans for each occurrence of `name` as a substring and accepts it only if the characters immediately before and after aren't identifier characters (letter, digit, `_`, `$`) — or are the start/end of the text. So searching for `Foo` matches `Foo.bar` and `new Foo()` but not `FooBar` or `myFoo`. An empty name never matches.

It's a plain text scan with no awareness of Java syntax, so it can't tell a real reference from the name appearing in a comment or a string. This is a deliberate copy of `spec::contains_identifier`, kept here so the Java pack doesn't depend on the spec-rendering module.
### Depends on
- (none)
